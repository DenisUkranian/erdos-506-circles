# Erdős Problem 506 — publication-grade closure audit

Date: 24 August 2026

This report distinguishes three different claims:

1. **Integrity:** the published files are the files that were intended to be released.
2. **Replay:** the supplied programs and retained certificates pass their declared checks.
3. **Mathematical closure:** every reduction is correct, every finite branch is covered, the theorem matches the intended problem, and the result has survived independent review.

Passing (1) and (2) does not by itself establish (3).

## 3. Important reproducibility qualification

The current command

```bash
python3 verify.py --full
```

must not be described as regenerating every expensive search from scratch.

It compiles and reruns many proof engines, but for several long computations it audits retained exact logs and finite certificate tables. In particular:

- `n=12` audits retained outputs for the 4479 general branches, the long `B=67` searches and the `B=68,r=0` component searches; complete regeneration is a separate `run_full.sh --regenerate` path;
- the `B=80`, `B=81` and `B=82` aggregate packages mostly verify retained branch outputs and coverage tables rather than repeating every multi-billion-node search;
- `B=83` performs a substantially fresh replay.

Recommended wording is **full certificate audit and selected fresh replay**, with **exhaustive regeneration** documented separately.

## 4. Unresolved self-contained replay gap at n=10

The `n=10` dependency tree contains two necessary non-complementary max-5-circle sweeps:

- 61 AA branches;
- 61 AB branches.

The supplied drivers regenerate DIMACS instances, but replay requires the external package `cadical-wasm@0.1.2`. The solver is not vendored, and the canonical release does not include independently checkable DRAT/LRAT UNSAT certificates for those 122 branches. The outer `verify.py --full` intentionally runs only the dependency-free core and therefore does not replay these necessary branches.

This does not show that `f(10)=33` is false. It does mean that `v1.0.0` alone is not a fully self-contained proof of the complete theorem.

Publication-grade remedies, in preferred order:

1. generate DRAT/LRAT proofs for all 122 UNSAT instances and include a small checked verifier;
2. replace the sweeps with a dependency-free exact DFS/SAT implementation;
3. at minimum vendor or cryptographically pin the solver binary/package and clearly list it in the trusted computing base.

## 5. The theorem scope omits n=4,5,6,7

The official problem asks for a sequence beginning at the first admissible cardinalities. The current manuscript proves `f(8)=17` and the uniform formula for `n>=9`, but the title reads as if the entire minimum sequence were determined.

Under the same nondegeneracy convention, a separate public Lean package states and formalizes

```text
f(4)=3, f(5)=5, f(6)=8, f(7)=11, f(8)=17,
f(n)=1+C(n-1,2)-floor((n-1)/2) for n>=9.
```

The present repository should either explicitly scope its main theorem to `n>=8`, or add the small values with proofs and proper attribution.
